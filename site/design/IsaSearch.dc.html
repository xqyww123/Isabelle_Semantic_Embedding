isasearch

Search Isabelle/HOL and the Archive of Formal Proofs by describing what you want in English. The index covers theorems and the rules that Isabelle derives from datatype, inductive and function definitions, and also constants, types, classes, locales, proof methods and named theorems: 1 362 163 entities in total.
A query is required, and it ranks the results. The syntactic filters are optional, and they decide which results can appear at all. A query cannot narrow the results, and the filters cannot rank them.

Looking for a name that you only partly remember? Type it into the search box and add it to an Entity Name condition as well. The condition keeps only the entities whose names contain what you typed, as whole parts; the query decides their order.

04  EMPTY STATE — AN EXPRESSION CONDITION MATCHED NOTHING (generic: nothing here assumes what the visitor meant)
isasearch
▾ Syntactic filters 1 condition expression: ?n + ?m = ?m + ?n
0 results Nothing contains that text
An Expression condition matches text, not patterns. It has no variables: ?n searches for the name n.
Your condition 
?n + ?m = ?m + ?n
isasearch removes the question marks — from your condition and from the text it searches — and then looks for 7 parts, one directly after another, in this order: n + m = m + n
Why this usually happens 
?a + ?b = ?b + ?a
A condition names its variables, and the same statement is printed with whatever names its author chose. The theorem you want is in the index — Groups.ab_semigroup_add_class.add.commute prints as above. The variable names are the only difference.
What to do instead: describe the statement in the search box — addition is commutative — and use an Expression condition only for a name that must appear, such as sorted_wrt.
What an Expression condition matches
yesNames and operators, as the card prints them: continuous_on, sorted_wrt, ⟦
no Variables and unification: ?f ?x, _ + _
yesWhole parts of a name, in order: sorted matches sorted_wrt; sort does not, because part of a part is not a part
no Regular expressions or wildcards: .*, cont*
yesIsabelle’s ASCII form: \<Longrightarrow> is always understood as ⟹; an unambiguous abbreviation such as ==> is replaced in the box while you type
no Question marks, _, . and the sub- and superscript marks: they divide a name into parts and are not matched themselves, so f⇩1 is found by f
To search by the structure of a term, describe it in the search box above — that is what the query is for. Inside an Isabelle session, find_theorems and find_consts search structurally. How the two differ

Error_Function  /  theorem

Error_Function.continuous_on_linepath'

Theorem Introduction rule
Statement 
⟦continuous_on ?A ?f; continuous_on ?A ?g; continuous_on ?A ?h⟧
⟹ continuous_on ?A (λx. linepath (?f x) (?g x) (?h x))
In English MACHINE-GENERATED

If functions f, g, and h are each continuous on a set A, then the map x ↦ linepath (f x) (g x) (h x) is continuous on A. The linepath combinator constructs the straight-line path between two points, so continuity of the endpoint functions transfers to continuity of the parametrised path.

Written by a language model from the formal statement, not by the theory’s authors. It may be imprecise or wrong. Where the explanation and the statement disagree, the statement is the correct one. isasearch searches this text as well, so an entity with a poor explanation may rank lower than it deserves.
