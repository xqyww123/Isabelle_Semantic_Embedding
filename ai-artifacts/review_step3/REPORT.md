### F3 — `_run_agent`'s catch-all recycle arm can swallow the gate task group's abort, leaving the run to drain the queue and then hang
*Ruling:* fix-then-rereview  *Severity:* major

Stands; both reviewers confirmed with measured runs of the real `_run_agent`, and I reproduced the asyncio core myself on this interpreter (Python 3.12.3): after a TaskGroup abort cancels the parent, a teardown that converts the CancelledError into an ordinary exception is caught by `except Exception` at :1039 with `asyncio.current_task().cancelling() == 1`, the `await asyncio.sleep(2)` completes normally, the loop recycles, and every subsequent `create_task` is refused with 'TaskGroup ... is shutting down'. One broken store therefore produces both halves at once. claude_code.py:490-493 awaits the subprocess transport's `__aexit__` during the same unwind and is a second such teardown. The measured end state is not merely wasted turns: `start_gate` increments `gates_running` before `create_task`, so every refused gate strands the counter, the entry sits in `_GATING` (so `unanswered()` is empty), and when the queue drains `_run_agent` parks in `wait_for_progress()` on an event only `enqueue` or `gate_finished` can set -- neither of which can fire again. `interpret_file` never returns and the Isabelle RPC call never completes, blocking the ML thread for the whole cone; the reviewers measured 18 further paid turns before the park. Both reviewers verified the proposed guard does not false-positive on a driver's own `asyncio.wait_for`, because 3.12's `wait_for`/`timeout` call `uncancel()` before raising TimeoutError. Routing: this is a plain bug, but the remedy adds a new rule to the run loop's recovery arms, which §15.4 specifies as 'exactly today's handlers ... with two changes'; the resulting loop and its regression test should be looked at again, so fix-then-rereview rather than fix.

**Fix / question:** Refuse to recycle a session whose task is being cancelled. Put the rule in one named helper and call it first in all four recovering arms (ReachLimit :1008, RateLimit :1012, PoisonedSession :1017, catch-all :1039) -- not only the last two, since a driver that classifies a teardown failure as a rate limit hangs identically after a 20-minute sleep:

        """A cancellation a driver's teardown replaced must not be recycled:
        the gate task group is tearing this session down."""
        t = asyncio.current_task()
        if t is not None and t.cancelling():
            raise

(`raise` inside the helper re-raises the exception being handled at the call site.) Land it together with F4's ordering fix.
